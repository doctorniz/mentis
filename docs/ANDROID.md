# Android

The mobile app is the same Tauri shell as the desktop app, built for Android.
iOS is kept possible (`cfg(mobile)` rather than `cfg(target_os = "android")`
where the code is not Android-specific) but needs a Mac to build.

- **Application id:** `app.mentis` (`src-tauri/tauri.android.conf.json`). The
  desktop app keeps `app.mentis.desktop`.
- **Front end:** `vite build --mode mobile` — `__MENTIS_DESKTOP__` (native
  index, no sqlite-wasm) and `__MENTIS_MOBILE__` (no tray, hotkey, launch at
  login, capture overlay) are both true.
- **Android project:** `src-tauri/gen/android`, generated by
  `tauri android init` and committed. App-specific Kotlin lives in
  `app/src/main/java/app/mentis/`.

## Vaults: a folder the user picks

A vault is a folder picked through Android's Storage Access Framework. Its
root is a `content://` tree URI (optionally `|folder` for a vault created
inside the picked folder), kept in the recent list with a display name.

- `src-tauri/src/saf.rs` — the Rust end; `vault_*` commands send `content://`
  roots here and plain paths to the file system, so the window does not know
  the difference.
- `SafPlugin.kt` — folder picking, with permission kept across launches. It
  needs the activity, so it is a Tauri plugin.
- `SafStore.kt` — everything else: path → document lookup (built directly for
  phone storage, looked up and cached for other providers), listing, and file
  descriptors for reads and writes, so file bytes never pass through a bridge.
  Rust calls it over JNI from its own threads (`saf.rs`), so calls run in
  parallel and never wait on the UI thread. R8 keeps it (`proguard-mentis.pro`).
- Speed: each document open costs ~40 ms on the emulator, almost all of it in
  Android's document provider; reading several at once brings a first index of
  2,000 notes to ~45 s. Later launches only re-list folders.
- No file watching: Android offers none for these folders. The vault is
  reconciled whenever the app comes back to the foreground.

## Reminders

The app is stopped in the background, so reminders are handed to Android
(`Reminders.kt`, through `ShellPlugin.scheduleReminders`): exact alarms that
post a notification with **Snooze 10 min** and **Done**. Those buttons work
without opening the app — the notification goes away, a snooze is alarmed
again, and the choice waits in Kotlin until the app next runs, when it is
written into the item's file as if chosen then
(`src/lib/reminders/notification-actions.ts`). Tapping the notification opens
the item. The schedule is kept so it is set again after a reboot.

The notification plugin is used only to ask permission to notify. On the
phone the app shows no in-app card for a reminder that falls due while it is
in the background, and no "missed" summary: Android delivered them.

Alarms are exact: `USE_EXACT_ALARM` (Android 13+, allowed for reminder and
calendar apps) and `SCHEDULE_EXACT_ALARM` up to Android 12. Without them
Android may deliver a reminder up to an hour late.

## Shares and quick capture

Android hands the app things to show through the activity's intents; `Inbox.kt`
keeps them until the web app takes them (`launch-inbox.ts`, on start and when
the app comes back), and `src/modules/capture/share-host.tsx` acts on them:

- **Shared text** goes straight to Thoughts, with Undo — unless it holds a
  link, which opens the Bookmark confirmation, prefilled (the sharing app's
  subject as the title).
- **Shared images** are copied into the app's cache while Android's grant to
  read them lasts, then saved to the vault's attachments folder
  (`attachmentFolder`, `_assets` by default); `inbox_read_file` reads each copy
  once and removes it.
- **App shortcuts** (long-press the icon; `res/xml/shortcuts.xml`): Capture,
  New task, Today's journal. **Widget** and **Quick Settings tile**
  (`QuickCapture.kt`): open straight into capture. The capture bar on screen
  takes the focus request (`requestCaptureFocus` in the UI store).

## Touch

Narrow screens (the phone app and the web app on a phone) share one layout:

- A bottom tab bar (`mobile-tab-bar.tsx`): Vault, Capture, Organizer, Search,
  More (the menu sheet). Hidden while the on-screen keyboard is up.
- The page draws under the status and navigation bars (`viewport-fit=cover`);
  `safe-top` / `safe-bottom` / `safe-x` utilities in `globals.css` keep content
  clear of them.
- Gestures: swipe a task right to complete, left to delete (with Undo);
  swipe between days in Journal and Calendar (`use-swipe.ts`); swipe down from
  the top of a dialog or sheet to close it; press and hold a list item, then
  drag, to reorder (`use-hold-to-reorder.ts`, mouse too). A swipe inside a
  scroll area needs `touch-pan-y` on that area: `touch-action` is only read up
  to the nearest scroll container.
- Android back (`touch-shell.ts`): closes the open dialog or sheet, then steps
  back through views visited, then sends the app to the background.

## Building and running

```bash
export ANDROID_HOME="$LOCALAPPDATA/Android/Sdk"
export NDK_HOME="$ANDROID_HOME/ndk/27.1.12297006"
export JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"

# Emulator (x86_64). Debug info makes the debug APK ~350 MB; without it ~180 MB.
CARGO_PROFILE_DEV_DEBUG=0 npx tauri android build --debug --target x86_64 --apk
adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
```

A debug build's webview can be driven from Playwright: forward
`localabstract:webview_devtools_remote_<pid>` with `adb forward` and use
`chromium.connectOverCDP`. The folder picker is system UI; drive it with
`adb shell uiautomator dump` and `adb shell input tap`.

## Cold start

When the app shell is ready, the app reports the activity fully drawn, so
Android logs `Fully drawn app.mentis/.MainActivity: +N ms` measured from
process start. Measure a release build (a debug build is unoptimised):

```bash
npx tauri android build --target x86_64 --apk
apksigner sign --ks ~/.android/debug.keystore --ks-pass pass:android \
  --out mentis.apk src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release-unsigned.apk
adb install -r mentis.apk
adb shell am force-stop app.mentis && adb logcat -c
adb shell am start -W -n app.mentis/.MainActivity
adb logcat -d | grep "Fully drawn"
```
